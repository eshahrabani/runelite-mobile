# Core JRE stubs

**Audience:** developer
**Read this when:** you need to understand, add, or regenerate the `java.*`/`javax.*` classes in `core/` that stand in for the desktop JRE the RuneLite client was compiled against.
**Verified against:** `core/build.gradle`, `tools/gen_stubs.py`, `tools/RefScan.java`, `tools/JdkInfo.java`, `tools/HostLinkCheck.java`, `android/build.gradle`, `core/src/main/java/java/awt/Graphics.java`, `core/src/main/java/java/awt/Graphics2D.java`, `core/src/main/java/java/awt/image/BufferedImage.java`, `core/src/main/java/java/awt/image/DirectColorModel.java`, `core/src/main/java/java/awt/AWTEvent.java`, `core/src/main/java/java/awt/Window.java`, `core/src/main/java/org/runelite/mobile/bridge/{AWTBridge,TextBridge,UiBridge,SwingEdt}.java`

`core/` is a plain `java-library` module (`core/build.gradle`) with no dependencies. It
holds three kinds of code:

1. **Hand-written `java.awt`/`javax.swing` implementation** — the port's stand-in for the
   desktop JRE surface RuneLite's own Swing shell needs: pixel/text code (`Graphics`,
   `Graphics2D`, `Image`, `BufferedImage`, `Font`, `FontMetrics`), the layout managers
   (`BorderLayout`, `GridLayout`, `FlowLayout`, `CardLayout`, `GridBagLayout`,
   `BoxLayout`/`Box`, `GroupLayout`, `JViewport.ViewportLayout`), the widgets
   (`JTable`/`JTree`/`JTextComponent`/`text/*`, `plaf/*`, borders, `UndoManager`,
   `HTMLEditorKit`, …), and the AWT hierarchy they build on. Behaviour is in
   [swing-runtime.md](swing-runtime.md).
2. **Generated data-only stubs** (identifiable by their marker header) for the rest of the
   surface the pre-compiled jars link against but the port never runs — `javax/management`,
   `javax/sound/sampled`, `com/sun/net/httpserver`, `javax/accessibility`, and the
   remaining `java.awt` subpackages.
3. **Port-only helpers and JRE replacements** (`org.runelite.mobile.**`), including the
   classes that stand in for JRE facilities ART lacks (`UnsafeHelper`, `ProcessHandle`,
   `ImageIO`).

The runtime side of the class-loader arrangement is in
[architecture.md](architecture.md); the build pipeline that generates and links this
code is in [build-and-release.md](build-and-release.md).

## 1. Why `java.*` can legally exist here

A normal javac would reject `package java.awt;` in user code ("package exists in
another module"). `core/build.gradle` compiles with:

```gradle
tasks.withType(JavaCompile) {
    options.compilerArgs.addAll(['--limit-modules', 'java.base,jdk.unsupported'])
}
```

`--limit-modules` shrinks the observable JDK to `java.base` and `jdk.unsupported`.
`java.desktop`, `java.logging`, `java.sql`, `java.naming`, `java.scripting`, and
`java.instrument` are no longer observable modules, so `java.awt.*`, `java.applet.*`,
`javax.swing.*`, etc. are **not** in a named module — and defining them in the
unnamed module is legal. `jdk.unsupported` stays because some client code still links
`sun.misc.Unsafe` (rewritten later, §3).

Two consequences:

- **Never remove the flag.** Without it, every `java.awt`/`javax.swing` source file
  fails to compile, and the classpath would instead resolve to the real desktop JDK
  at build time and to nothing on ART.
- **Never add a `java.*` package that a retained module already defines.** Only
  packages absent from `java.base`/`jdk.unsupported` may be shadowed this way.

`hostshims/` is compiled with the same flag pattern by `compileHostShims(File)` in
`android/build.gradle`, because the shims also replace classes from the desktop
`java.desktop` surface.

## 2. Hand-written vs generated

A file is **hand-written** iff the marker string `Data-only stub for {@code` does **not**
appear in its first 4096 bytes (the `MARKER` constant and the `handwritten` classification
loop in `tools/gen_stubs.py`; the scan covers both `core/src/main/java` and
`hostshims/src`). Generated files carry a header ending
`Generated by tools/gen_stubs.py -- do not hand-edit.` The marker is the only reliable
discriminator: do not use git status, and do not assume a package is entirely one kind —
`javax/swing` is almost all hand-written, yet `javax/swing/JFrame.java` is generated.

| Generator-marked (generated) | 51 |

The only generated `javax/swing`/`java/awt` files are the ones whose members the client
references but whose packages are otherwise hand-written: `javax/swing/JFrame`,
`RootPaneContainer`, `TransferHandler`, and scattered `java/awt`/`java/awt/event`/
`java/awt/geom` types (`SystemTray`, `TrayIcon`, `Taskbar`, `WindowAdapter`,
`MouseMotionAdapter`, …).

Rules:

- **Generated files are rewritten on every generator run.** Editing one by hand is
  lost at the next run; the header says so.
- **The generator never overwrites a hand-written file.** If the target path exists
  and lacks the marker, it is skipped. Stale *generated* files (marker present) are
  deleted; hand-written files are never deleted.
- **To change a generated stub's membership, change the generator's inputs**
  (the client jars scanned by `RefScan`), not the file. See [tools.md](tools.md).

The generator is a **manual** step. Its docstring claims it is "wired as the
`:android:generateJdkStubs` Gradle task"; no such task exists and no `*.gradle` file
references `gen_stubs`. Invoke the script by hand after a client bump; the regeneration
command is in [tools.md](tools.md).

## 3. JRE-replacement helpers

Three hand-written replacements stand in for a JRE facility ART does not provide.
Unlike the port-only helpers in §7, these preserve an API the client already uses.

| Class | Replaces | Mechanism |
|---|---|---|
| `org.runelite.mobile.UnsafeHelper` | `sun.misc.Unsafe` | build-time ASM rewrite |
| `org.runelite.mobile.ProcessHandle` / `ProcessHandleImpl` | `java.lang.ProcessHandle` | build-time ASM rewrite |
| `javax.imageio.ImageIO` | desktop `ImageIO` | compile-time core class; Android reflection at runtime |

**`UnsafeHelper`** exposes `ARRAY_*_BASE_OFFSET`/`ARRAY_*_INDEX_SCALE` ints and
`copyMemory(...)` overloads (`core/src/main/java/org/runelite/mobile/UnsafeHelper.java`).
Its static initialiser reads `sun.misc.Unsafe.arrayBaseOffset/arrayIndexScale`
reflectively and falls back to hardcoded 32-bit defaults (base 12/16, scale
1/2/4/8) when reflection is unavailable. `copyMemory` is an 8-byte-then-byte copy
loop over null/non-null base combinations. `transformClassBytes` (in
`android/build.gradle`) rewrites `GETSTATIC sun/misc/Unsafe.ARRAY_*` and
`INVOKEVIRTUAL sun/misc/Unsafe.copyMemory` to the static helper, appending a base
argument to the copy call.

**`ProcessHandle`** is an interface with `info()`, `parent()`, and static
`current()`; **`ProcessHandleImpl`** is a singleton whose `command()` is the literal
`"runelite"` and whose `parent()` is empty. The build rewrites
`java/lang/ProcessHandle` to `org/runelite/mobile/ProcessHandle` across signatures,
field/method descriptors, `LDC` types, `NEW`, and call sites (also in
`transformClassBytes`).

**`javax.imageio.ImageIO`** is hand-written. `getImageReadersByFormatName` returns a
single anonymous `ImageReader` backed by a `MemoryCacheImageInputStream`, and
`read(InputStream)`/`read(File)` decode PNG/JPEG by reflecting
`android.graphics.BitmapFactory.decodeStream` → `Bitmap.getPixels` →
`new BufferedImage(pixels, w, h)`. Reflection is mandatory: `core/` is compiled
with `--limit-modules java.base,jdk.unsupported` and must not reference `android.*`
directly. Decode failure logs to `System.err` and returns an empty `BufferedImage`
rather than throwing. `read(File)` delegates to `read(InputStream)` so there is one
decode path.

## 4. The AWT bridge

The bridge that carries the host↔core contract across the module boundary lives in
`core/src/main/java/org/runelite/mobile/bridge/`:

- **`AWTBridge`** — the static display buffer and UI-thread façade.
- **`TextBridge`** — the platform text-rasteriser interface (implemented in the app dex
  by `AndroidTextRenderer`).
- **`UiBridge`** — the Swing stage contract (sidebar/window geometry, paint, input); the
  app implements it in `SwingSidebarView` and `SwingWindowLayer`.
- **`SwingEdt`** — the event dispatch thread (`Swing-EDT-rlmobile`) and the nested
  `pumpUntil` loop a modal dialog needs.
- **`PopupLayer`** — the core-side stack of menus/drop-downs/tooltips.

`UiBridge`/`SwingEdt`/`PopupLayer` and the Swing paint model are documented in
[swing-runtime.md](swing-runtime.md); this section covers only the display-buffer and
text contract.

**`AWTBridge`** is the static display-buffer and UI-thread bridge:

| Member | Kind | Consumer |
|---|---|---|
| `activePixels` / `activeWidth` / `activeHeight` | `static volatile` | read by the render path; installed by `MainActivity.onCreate` |
| `registerUiThread(Thread, Executor)` | static | installed once by `MainActivity.onCreate` (`SwingEdt.ensureStarted()` + `SwingEdt::post`) |
| `swingThread()` | static | the registered thread, else the default `SwingEdt` |
| `isUiThread()` | static | AWT contract checks |
| `post(Runnable)` | static | enqueues on the registered executor, else the `SwingEdt` queue |
| `invokeAndWait(Runnable)` | static | runs inline when already on the EDT, else blocks on a `CountDownLatch` and rethrows as `RuntimeException` |
| `MousePathSmoother.generatePath` | nested static | retained path-smoothing helper (no caller outside this file) |

RuneLite's contract is "plugins run on the event dispatch thread": the host registers the
port's Swing EDT so that code which would post to the EDT
(`SwingUtilities.invokeLater/invokeAndWait`, `PluginManager`'s EDT assertion) posts
through this façade instead.

**`MobilePoint`** is an immutable `x`/`y` holder replacing `java.awt.Point`; it is
retained only for `MousePathSmoother` and is otherwise unused.

**`TextBridge`** (`core/src/main/java/org/runelite/mobile/bridge/TextBridge.java`) is
the interface to the platform text rasteriser. `core/` cannot rasterise TrueType
fonts (and cannot reference `android.graphics.*`), so the app dex supplies an
`AndroidTextRenderer` through the nested `TextBridge.TextRenderer` installed in
`TextBridge.renderer`. `createFont`, `stringWidth`, `height`, `ascent`, `descent`, and
`drawString` all delegate to it and degrade to a deterministic approximation (6 px per
character for width, point size for vertical metrics) when no renderer is installed.
`drawString` returns `false` when the platform could not paint, so the caller falls
back instead of dying.

### Static/instance contract

`tools/HostLinkCheck.java` (run by `:android:verifyHostLinks`) enforces the call-site
shape rule that decides whether a member must be static (`shapeMismatch`):

- `INVOKESTATIC` (flag `S`) requires the resolved member to be static.
- `INVOKEINTERFACE` (`I`) requires the declaring class to be an interface.
- `INVOKEVIRTUAL`/`INVOKESPECIAL` (`-`/`E`) require a non-static member.

The generator decides staticness the same way — **by the use-site opcode, not by the
JDK's own declaration** (`tools/RefScan.java`: `flag(opcode, INVOKESTATIC)`;
field `GETSTATIC`/`PUTSTATIC` ⇒ `S`). If a stub is declared static when the call site
is `INVOKEVIRTUAL` (or an interface method when the call site is not), ART raises
`IncompatibleClassChangeError` at link time.

The worked example is `javax.swing.text.StyleContext.getDefaultStyleContext()`: the
client's call site is `INVOKESTATIC`, so the hand-written stub declares it `static`
(`core/src/main/java/javax/swing/text/StyleContext.java`). It could not be generated
as a data-only method returning `null` — `FontManager.<clinit>` calls
`getFont("RuneScape", …)` on the result, and a `null` there poisons the class for the
whole process (`NoClassDefFoundError` for every later user). `HostLinkCheck` verifies
the resulting shape against app dex + asset dex + `android.jar` + runtime jars; see
[tools.md](tools.md) for the resolution algorithm.

## 5. Graphics/Image semantics

`Graphics` draws into a **shared non-premultiplied ARGB `int[]`**
(`core/src/main/java/java/awt/Graphics.java`). `destHasAlpha` records whether the
destination pixels carry meaningful alpha; it is seeded from `Image.hasAlpha` when the
context is bound (`Graphics(Image)`).

`blendPixel` scales source alpha by `compositeAlpha`. On the common `SRC_OVER` path
when `!destHasAlpha` it blends RGB and **preserves the destination alpha byte** — so
drawing over the game frame, whose pixels are alpha 0, blends visually instead of
turning the frame opaque. When `destHasAlpha` it performs full source-over with the
un-premultiplied divide by `outA`. The remaining Porter-Duff rules (`CLEAR`, `DST`,
`SRC_ATOP`, …) go through `blendRule`.

`drawImage` keeps **branch-free opaque fast paths**, gated by `img.hasAlpha` and a
source-copy composite:

| Source | Path |
|---|---|
| opaque, 1:1 size, source-copy composite | one `System.arraycopy` per row — the game's every-frame path (`drawImageDevice`) |
| opaque, scaled | divide-free nearest-neighbour accumulator stepping `srcX`/`srcY` (`scaleBlit`); a `KEY_INTERPOLATION` hint switches to centre-aligned bilinear `sampleBilinear` |
| `hasAlpha`, or a non-default `AlphaComposite` | per-pixel `blendPixel` (inside `scaleBlit`) |

A rotated/sheared draw samples the source through the inverse transform
(`drawImageMapped`). The game frame stays opaque through `BufferedImage.getRGB`:
`getRGB` returns `colorModel.getRGB(pixel)`
(`core/src/main/java/java/awt/image/BufferedImage.java`), and
`DirectColorModel.getRGB` has an opaque fast path — when `alphaMask == 0` it returns
`0xFF000000 | (pixel & 0xFFFFFF)` (`core/src/main/java/java/awt/image/DirectColorModel.java`).
The game frame is built with a 3-mask `DirectColorModel(32, 0x00FF0000, 0x0000FF00,
0x000000FF, alpha ? 0xFF000000 : 0)`, so its alpha mask is zero and overlays blended
into it are presented without corruption.

`getGraphics()` returns a `Graphics2D` (`BufferedImage.java`; `Image.getGraphics()`
returns `new Graphics2D(this)` — `core/src/main/java/java/awt/Image.java`). This is
load-bearing: `net.runelite.client.callback.Hooks` casts the result to `Graphics2D`,
so a plain `Graphics` would be a `ClassCastException` there.

Text: `Graphics.drawString` passes the effective scale to `TextBridge.drawString`;
`FontMetrics` routes through `TextBridge` and falls back to `str.length() * 6` /
point-size metrics with no renderer (`core/src/main/java/java/awt/FontMetrics.java`).
The why is in §4.

### Documented fidelity limits

A reader must know which `Graphics2D` calls are decorative:

| Limit | Behaviour |
|---|---|
| Shape anti-aliasing | `KEY_ANTIALIASING` is accepted and stored, but geometry is rasterised with hard edges (`core/src/main/java/java/awt/Graphics2D.java`) |
| Non-solid paints | `GradientPaint` is rasterised along its two transformed endpoints; any other non-colour `Paint` falls back to the last solid colour (`Graphics2D.setPaint`) |
| `GeneralPath` | stores `moveTo`/`lineTo`/`closePath` only; curves degrade to the current point (`core/src/main/java/java/awt/geom/GeneralPath.java`) |
| `Area` | modelled as added-shapes minus subtracted-shapes; no exact boolean path arithmetic, `contains` is approximate (`core/src/main/java/java/awt/geom/Area.java`) |

`Graphics2D.drawOrFill` routes `Line2D`/`Ellipse2D`/`Arc2D`/`RoundRectangle2D`/
`Rectangle(2D)`/`Polygon`/`GeneralPath`/`Area` to primitive raster calls and otherwise
falls back to the shape's `getBounds()`. Text is anti-aliased by the platform text
bridge, not by the software rasteriser.

## 6. Event stubs

`java/awt/event` has 34 files (2 generated — `WindowAdapter`, `MouseMotionAdapter` — 32
hand-written). The hand-written event classes carry members that the generated
data-only pass cannot invent and that are device-only `NoSuchMethodError`s when absent:

| Member | File | Note |
|---|---|---|
| `AWTEvent(Object,int)` | `core/src/main/java/java/awt/AWTEvent.java` | the runtime-critical constructor |
| `MouseEvent.getComponent()` / `getPoint()` | `java/awt/event/MouseEvent.java` | cast of `getSource()`; `new Point(x,y)` |
| `MouseEvent.getModifiersEx()` override | `java/awt/event/MouseEvent.java` | sets the pressed button's down-mask |
| `MouseWheelEvent(Component,…)` | `java/awt/event/MouseWheelEvent.java` | passes `NOBUTTON` to `MouseEvent` |
| `InputEvent.getModifiersEx()` / `getModifiersExText(int)` | `java/awt/event/InputEvent.java` | stored modifiers; `"Shift, Ctrl, Button1"` text |
| `KeyEvent.getKeyText(int)` / `getExtendedKeyCode()` / `setKeyCode` / `setKeyChar` / `paramString()` | `java/awt/event/KeyEvent.java` | names/round-trips the `VK_*` constants |

`java/awt/Window` is a hand-written **virtual window**
(`extends Container implements RootPaneContainer`): it owns a `JRootPane`
hierarchy, an owner, size/location, visibility and the listener sets, and
`setVisible(true)`/`dispose()` register/unregister it with
`org.runelite.mobile.bridge.UiBridge` so the app paints it (`SwingWindowLayer`).
It is not a source of the `IncompatibleClassChangeError` class of failures above;
see [swing-runtime.md](swing-runtime.md).

`AWTEvent` is hand-written because the client never names one of its members
directly, so a call-site scan would not emit it — but the core event stubs extend it
and call `super(source, id)`. Getting it wrong is invisible at build time and fatal
at runtime: the game's own UI event dispatch creates `ActionEvent`s on the client
thread (`ActionEvent` calls `super(source, id)`), and a missing
`AWTEvent(Object,int)` stops that thread with a `NoSuchMethodError` — the frame
freezes. The class javadoc documents this, and the class also carries a no-arg
constructor for generator compatibility.

Dispatch failure is silent except in logcat. If a tap logs `Dispatch mouse id=501 …`
and then nothing happens, one of the event-stub members above is missing and the
thrown `NoSuchMethodError` was caught as `Throwable` after the log line. The touch
path has the exact member list; see [input.md](input.md) and
[troubleshooting.md](troubleshooting.md).

### The two hand-written-stub rules

1. **No-arg constructor on hand-written supertypes.** The generator models a
   hand-written supertype as "a plain class with a no-arg constructor" and emits
   `super()` into every generated subclass (`super_args` in `tools/gen_stubs.py`). That
   is why `AWTEvent()` exists, and why the generated `javax.swing.JFrame` (whose super
   is the hand-written `java.awt.Frame`) emits `super()`. Keep the no-arg constructor
   when editing a hand-written supertype.
2. **A hand-written stub's supertype must also be hand-written** (or a generated file
   that the generator can re-emit). The generator only emits the classes the client
   *names*, so a supertype the client never references has to be provided by hand:
   `java.awt.image.RGBImageFilter` exists by hand solely so the hand-written
   `javax.swing.GrayFilter` (which `ImageUtil.grayscaleImage` calls) can link.
   Introducing a generated supertype under a hand-written class risks `super_args`
   choosing a constructor the hand-written class does not declare.

## 7. Port-only helpers

`org.runelite.mobile.**` classes exist for this port rather than the JRE. Link style
distinguishes a normal compile-time dependency from a build-time ASM injection;
the injection machinery is in [build-and-release.md](build-and-release.md).

| File | API | Caller | Link |
|---|---|---|---|
| `TileCompositor.java` | `setClassLoader`, `composite`, `compositeEnd`, `trace*` | ASM-injected into the client's software scene renderer | ASM-injected (`transformClassBytes`, `android/build.gradle`) |
| `MousePath.java` | `expand(x0,y0,t0,x1,y1,t1) -> long[]` | `MainActivity.emitSegment` | compile-time (app → core) |
| `UnsafeHelper.java` | `ARRAY_*` offsets/scales, `copyMemory` | rewritten `sun.misc.Unsafe` sites | ASM-injected (`transformClassBytes`) |
| `ProcessHandle.java` / `ProcessHandleImpl.java` | `info()`, `parent()`, `current()` | rewritten `java.lang.ProcessHandle` sites | ASM-injected (`transformClassBytes`) |
| `bridge/AWTBridge.java` | display buffer, UI-thread executor | `MainActivity`, `RuneLiteHost` | compile-time |
| `bridge/UiBridge.java` | Swing stage contract | app dex `SwingSidebarView` / `SwingWindowLayer` | compile-time |
| `bridge/SwingEdt.java` | EDT + `pumpUntil` | `AWTBridge` | compile-time |
| `bridge/PopupLayer.java` | popup stack | `UiBridge` paint/hit-test | compile-time |
| `bridge/TextBridge.java` / `bridge/MobilePoint.java` | text renderer interface; point holder | app dex `AndroidTextRenderer`; `MousePathSmoother` | compile-time |

**`TileCompositor`** holds read-only diagnostic hooks on the injected client's
software scene renderer. Its header states the world is drawn directly into the
display buffer, so there is no missing tile composite; the hooks sample the buffer
and count scene pixels to locate where rendering is lost. Every hook is wrapped in
`try/catch (Throwable)` that funnels to the private `hookFailed` sink
(`core/src/main/java/org/runelite/mobile/TileCompositor.java`), because the hooks
run inside the game's frame loop and none may throw into it. The injected call
sites reference client-internal obfuscated names (`client.ij`, `fu.ax`, `gp.em`,
`yw.es`, …) that are version-specific; they are re-derived on a client bump.

**`MousePath.expand`** splits a touch-sample segment into steps at most
`MAX_SEG_PX = 8` game pixels apart, capped at `MAX_FILL = 16` intermediate points,
returning a flat `[x, y, t, ...]` array that excludes the start and includes the
endpoint. It is pure arithmetic with no Android dependency. It is what makes
synthesized touch motion resemble a real mouse instead of one jumped event.

## 8. Housekeeping

- Hand-written stubs live in `core/` and must keep the properties their consumers
  depend on (no-arg supertype constructors, real static/instance shape, non-null
  factories such as `StyleContext.getDefaultStyleContext`).
- Generated stubs carry the `Generated by tools/gen_stubs.py -- do not hand-edit.`
  header. Never edit one; change the generator's inputs and regenerate.
- After a RuneLite client bump: regenerate the stubs, rebuild, then run
  `:android:verifyHostLinks` (see [build-and-release.md](build-and-release.md)).
  The regeneration command and the `gen_stubs.py`/`RefScan`/`JdkInfo` invocation
  details are in [tools.md](tools.md).
