# Code map

**Audience:** implementer
**Read this when:** you need to find which file owns a behaviour, or you are about to add, move, or delete a source file.
**Verified against:** `find android/src/main/java`, `find core/src/main/java`, `find hostshims/src`, `find tools`, `git ls-files`, `wc -l` on every listed file, `android/build.gradle`, `.gitignore`

This is the per-file catalogue: what each source file owns, how many lines it has, and which
loader consumes it. It is the deepest level of the documentation set; the subsystem behaviour
lives in the sibling pages linked below each table.

## How to read this file

Every file below carries a marker describing its provenance and its build role. Read the marker
before editing anything.

| Marker | Meaning | How it is produced |
|---|---|---|
| `app` | Hand-written app code. Compiled by the `:android` module into the app dex. | `android/src/main/java/**` |
| `stub-hand` | Hand-written JVM/AWT replacement. Compiled by `:core` into the app dex. Edit in place. | `core/src/main/java/**`, no generator marker |
| `stub-gen` | Generated JDK stub. **Never hand-edit**; a `gen_stubs.py` run rewrites it. | `core/src/main/java/**` carrying `Generated by tools/gen_stubs.py -- do not hand-edit.` |
| `shim` | Hand-written replacement for an upstream `net.runelite.client.ui.*` class. Compiled by `compileHostShims()` inside `android/build.gradle`, not by the app source set. | `hostshims/src/**` |
| `tool` | Build-time or developer tool, not shipped in the APK. | `tools/**` |

A file is treated as hand-written iff the marker string `Data-only stub for {@code` is absent from
its first 4096 bytes (`tools/gen_stubs.py:83-98`). This convention decides what the generator skips
and never overwrites: `tools/gen_stubs.py:645-649` refuses an existing marker-less target, and the
stale-file cleanup deletes a file only when it carries the marker (`tools/gen_stubs.py:660-669`).
See [tools.md](tools.md) for the generator itself and [core-stubs.md](core-stubs.md) for the
stub contract.
